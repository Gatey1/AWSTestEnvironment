A public web app with a database the internet cannot reach

A two-tier test environment on AWS: one web server in a public subnet, PostgreSQL in private subnets that only the web server can talk to, and every visit and login sent to CloudWatch with an email alarm on repeated failed logins.

Region ap-southeast-2 (Sydney) · built in the AWS Management Console · Python, Flask, nginx, PostgreSQL 17

What happens when someone logs in

  1. The browser sends the form to the server's public IP; the IGW routes it into the public subnet, where the web server's firewall allows port 80.
  2. nginx logs the request as a JSON line and passes it to the Flask app on localhost.
  3. The app fetches the database login from Secrets Manager using the instance's IAM role, which can read that one secret and nothing else.
  4. It queries PostgreSQL over TLS. The database answers only because the connection comes from the web server's security group.
  5. The app checks the password hash, records login_success or login_failure with the reason, and starts a signed session.
  6. The CloudWatch agent ships both log files. A metric filter counts failed logins, and five within five minutes trips the alarm, which emails the administrator.

What the app does

  • Public landing page, sign-up and login.
  • An account page where each user saves a favourite sport and car colour.
  • Every read and write on that page uses the user ID from the signed session, never one sent by the browser, so a user can only see their own row.
  • Passwords are stored as salted hashes, every form carries a CSRF token, and all SQL is parameterised.

Built with

  • Built by hand in the AWS Management Console: VPC, EC2, RDS, IAM, Secrets Manager, CloudWatch and SNS.
  • Amazon Linux 2023, nginx, gunicorn, Python 3.11, Flask, psycopg 3, boto3.
  • RDS for PostgreSQL 17 with the password managed by Secrets Manager.
  • CloudWatch agent, Logs Insights, metric filters, alarms and SNS.

What I would change for production

  • HTTPS: an Application Load Balancer with an ACM certificate, and secure-only session cookies. The test site serves plain HTTP.
  • No public instances: move the web server into the private subnets behind the load balancer, with VPC endpoints for Secrets Manager, SSM and CloudWatch instead of internet egress.
  • Resilience: an Auto Scaling group across both zones and Multi-AZ RDS, with deletion protection and final snapshots on.
  • Least privilege in the database: an application role with rights on its own tables, instead of the master user.
  • Abuse protection: AWS WAF rate limits on the login and sign-up routes.
  • Infrastructure as code: rebuild the environment in Terraform, so changes are reviewed, repeatable and easy to tear down, instead of clicked through the console.
  • Delivery: application releases through a pipeline and a launch template, rather than pasting update scripts into a shell.
